브라우저 기능 검증은 별도의 임시 DB와 가상 데이터, 합성 인증 컨텍스트를 사용하는 로컬 QA 하네스로 수행했습니다. 이 하네스와 테스트 DB는 배포 패키지에 포함하지 않았습니다. 운영 인증은 API 테스트에서 별도로 검증했습니다.

## 수행하지 못한 검증

- Docker 실행기가 없어 실제 Docker 이미지 빌드/실행은 수행하지 못했습니다. Python 의존성은 새 환경에 실제 설치하여 확인했습니다.
- 실제 Kubernetes 클러스터에서 Pod 생성, PVC 권한/바인딩, 레지스트리 인증, Ingress/TLS 및 외부 DNS 연결은 검증하지 못했습니다. 배포 환경에서 README의 설치 및 점검 명령을 실행해야 합니다.
- Microsoft Excel 데스크톱 애플리케이션에서 직접 열어 보는 검증은 수행하지 못했습니다. XLSX 압축/XML 형식과 별도 리더의 셀 타입·값은 검증했습니다.
- 모바일 기기 실기기 및 대규모 동시 사용자 부하 검증은 수행하지 않았습니다. 반응형 CSS는 포함되어 있습니다.

## 배포 후 확인

1. 이미지를 빌드하고 레지스트리에 푸시합니다.
2. Secret과 StorageClass/Ingress/TLS 값을 지정합니다.
3. `helm upgrade --install ... --wait` 실행 후 Pod가 Ready이고 PVC가 Bound인지 확인합니다.
4. `bash scripts/smoke_test.sh https://본인호스트`로 헬스체크와 미인증 API 차단을 확인합니다.
5. 로그인 후 프로젝트/일정/협력사 업무를 각각 등록하고 Excel 다운로드를 확인합니다.
6. Pod 재시작 후 데이터가 남아 있는지 확인합니다.
7. DB 백업을 수행하고 별도의 테스트 환경에서 복구를 검증합니다.

### 3rd-party / 개발사 개정 추가 검증

- 이름별 3rd-party 생성, 하위 진행사항 추가, 체크·체크 해제, 개발사 적용 완료 변경을 API와 브라우저에서 확인했습니다.
- 체크 취소선의 실제 CSS `line-through`, 해제 후 `none`, 새로고침 후 저장 유지와 이름 검색을 확인했습니다.
- 개발사 업무 등록 및 별도 탭 분리를 브라우저에서 확인했습니다.
- 프로젝트 Excel의 정확한 5개 시트명/순서와 모든 셀 스타일의 위쪽 정렬을 별도 XLSX 리더로 확인했습니다.
- 완료한 진행사항의 부분 취소선을 XLSX rich-text XML에서 확인했습니다.
- 파일명의 프로젝트명·항목·한국 날짜 조합과 허용되지 않는 문자 치환을 검증했습니다.
- 기존 협력사 자료의 ID와 메모 보존 및 중복 전환 방지를 검증했습니다.

### 체크리스트 자동 진행률 추가 검증

기본 7개 항목의 정확한 텍스트와 미완료 상태, 단계별 정수 반올림(14/29/43/57/71/86/100%), 체크 해제, 항목 수정·추가·삭제 및 전체 삭제 시 0%, 기존 사용자 목록 보존, 서버의 수동 진행률 덮어쓰기 방지와 Excel 자동 진행률 일치를 검증했습니다.

### 프로젝트 색상 추가 검증

개별 색상으로 프로젝트 생성·수정·재시작 후 저장 유지, 유효하지 않은 색상 차단, 기존 DB의 프로젝트/일정 보존을 테스트했습니다. 브라우저에서 파랑 선택 후 일정의 실제 테두리 RGB 확인, 보라색 변경 후 같은 일정에 반영 및 새로고침 후 유지, 다른 프로젝트 색상 보존을 확인했습니다.

### Helm 배포 패키지 확정

빈 PVC에서 DB/최초 관리자만 생성하며 사용자·샘플 데이터를 패키징하지 않습니다. HTTP/HTTPS 설정 각각 strict lint, 템플릿 렌더링, Deployment/Service/PVC 연결, HTTPS cookie 설정, 비루트·읽기 전용 설정, PVC 유지 설정을 확인했습니다. Docker 이미지와 실제 클러스터 실행 검증은 수행하지 않았습니다.
